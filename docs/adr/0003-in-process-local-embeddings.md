# In-process local embedding model instead of an external embeddings API

Embeddings are generated by a small CPU model running in-process inside the FastAPI app, not via an external embeddings API (OpenAI, Voyage, etc.) and not in a separate inference service. This keeps v1 to one deployable backend service with no per-embedding API cost or external dependency for this step.

The trade-off is embedding quality/throughput ceiling versus infra simplicity; because sync is a full resync (ADR-0002), switching models later just means re-running the sync, not a migration.
